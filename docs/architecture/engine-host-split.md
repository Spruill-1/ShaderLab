# Engine / Host Split

The codebase is divided between a host-agnostic engine DLL and one or more host applications:

- **`ShaderLabEngine.dll`** owns everything that doesn't need a UI thread or a swap chain: the `GraphModel` model + JSON serialization, the `GraphEvaluator` (per-node D2D effect cache, dirty propagation, two-pass evaluate), `SourceNodeFactory` (image / video / DXGI / WGC sources), `EffectRegistry` (40+ wrapped D2D effects + 38 ShaderLab effects with embedded HLSL), `DisplayMonitor` + ICC parsing, the `Effects/CustomPixelShaderEffect` / `CustomComputeShaderEffect` COM classes, the generic D3D11 compute dispatch helper (`Rendering/D3D11ComputeRunner.{h,cpp}`), the `ShaderCompiler` (D3DCompile + D3DReflect), and **the entire MCP protocol surface — the `McpRouter` route registry, JSON-RPC dispatcher, declarative tool catalog, session client, plus the 28 engine routes** (`Engine/Mcp/{McpRouter,McpTypes,McpJsonRpc,McpToolCatalog,McpSessionClient,EngineMcpRoutes}`, the routes in `Engine/Mcp/Routes/`, one file per concern) and the broker plumbing (`McpFrame` codec, `McpCrypto` ECDH/GCM stack, `McpChannel`, `McpPeerIdentity` pairing). The transport is the broker (shim → hub → session over named pipes). Engine-pure helpers extracted for reuse: `Rendering/PixelReadback.{h,cpp}` (FP32 RGBA region readback), `Rendering/CaptureNode.{h,cpp}` (node to PNG), `Rendering/ImageCapture.{h,cpp}` (the one readback and encode path: `ResolveNodeImage`, `GetImageBounds96Dpi`, `RenderToPixels`, which restores the context's target, DPI and transform on every path, `EncodePng`, `EncodeToFile`; the GUI's preview, graph snapshot and *Save image* use it too), `Rendering/DeviceStack.{h,cpp}` (the D3D11 + D2D device stack every host creates the same way: BGRA support, multithread protection, a multi-threaded D2D factory), `Rendering/WorkingSpaceSync.{h,cpp}` (Working Space parameter node refresh from one `DisplayProfile` value, no monitor needed), `Effects/NodeCatalog.{h,cpp}` (`CreateNodeByName`, behind `/graph/add-node` and `/graph/apply`), `Graph/PropertyWrite.{h,cpp}` (`WriteProperty`, the untyped property write behind `/graph/set-property` and `/graph/apply`), `Graph/ParameterModel.{h,cpp}` and `Graph/ClockModel` (parameter sliders and clock seek / play, so the canvas, MCP and headless share them), and `Engine/Mcp/McpArgs.h` / `McpSerialize.{h,cpp}` / `McpJsonWriter.h` (argument readers, JSON vocabulary including `NodeToJson`, and the JSON writer and error bodies, for both hosts' routes).

- **`ShaderLab.exe`** (the WinUI 3 host) keeps everything that genuinely needs WinUI: `MainWindow.xaml.{h,cpp}` (which itself is split into sibling partial TUs `MainWindow.WorkingSpace.cpp`, `MainWindow.GraphFileIo.cpp`, `MainWindow.RenderTick.cpp`, `MainWindow.McpRoutes.cpp` (the router and the engine sink), `MainWindow.McpAppRoutes.cpp` (the GUI's own routes) and `MainWindow.McpSession.cpp` (the hub session)), `Controls/McpRouteTable` (each GUI route's thread) and `Controls/PerfMcpRoutes`, `Controls/DialogCoordinator` (one ContentDialog at a time), `Controls/PropertiesPanelController` (the Properties panel, with `PropertyEditors` and `CurveEditorDialog`), `Controls/McpStatusIndicator` (the MCP activity dot), `Controls/NodeGraphController` (the canvas editor, with `NodeLayout`, `NodeGraphRenderer` and `GraphCanvasInputController`), `Controls/PreviewController` (preview input; the view itself is the engine's `Rendering::PreviewViewState`), `Controls/PixelTracePanelController` (the trace UI; the trace is the engine's `Rendering::TracePixel`), `Controls/OutputWindow` (per-Output OS window) with `OutputSinkRenderer`, the Effect Designer modal window (its scaffold is the engine's `Effects::GenerateEffectScaffold`), and `RenderEngine` (the preview swap chain and `SwapChainPanel` binding over an engine `DeviceStack`, plus the render worker's own D2D context).

- **`ShaderLabHeadless.exe`** (see below) reuses everything from the engine DLL with no WinUI dependency.

- **`ShaderLabMcpBroker.exe`** is the odd one out: it does **not** link the engine at all. The hub must start in milliseconds and never touches a GPU, so it compiles the small transport-only `Engine/Mcp/Mcp{Frame,Crypto,Channel,PeerIdentity}` translation units directly into the exe. It runs as the MSIX package's second `<Application Id="Hub">` (hidden, full-trust) and as an unpackaged `--stdio` shim copied out of the package.

## `IEngineCommandSink` event hook architecture

When MCP routes mutate engine state, they fire through an `IEngineCommandSink` (`Engine/Mcp/EngineMcpRoutes.h`) so that:

1. The host marshals the mutation closure to whatever thread is appropriate. The GUI host routes to the **render worker thread** via `RenderThreadDispatcher::DispatchSync` so `m_graph` stays single-writer; the headless host runs the closure inline since there is no separate consumer.
2. The host runs **event hooks** afterwards. Hooks may need to touch XAML (which is STA-only), so the GUI sink re-marshals UI work back to the UI thread via `DispatcherQueue().TryEnqueue` from inside the render-thread closure.

The eight hooks are: `OnNodeAdded`, `OnNodeRemoved`, `OnNodeChanged`, `OnGraphCleared`, `OnGraphLoaded`, `OnGraphStructureChanged`, `OnCustomEffectRecompiled`, `OnDisplayProfileChanged`. The GUI's `MainWindow::GuiEngineCommandSink` overrides each one to call the same UI methods that handle native user interactions (`AutoLayout`, `RebuildLayout`, `PopulatePreviewNodeSelector`, `PopulateAddNodeFlyout`, `UpdateStatusBar`, `MarkAllDirty`, `CloseOutputWindow`, `ResetAfterGraphLoad`). The headless host leaves each hook as the default no-op. **Result: an MCP client calling `/graph/add-node` triggers exactly the same downstream UI code path as the user clicking the toolbar.**

A ninth hook, `OnGraphMediaDirChanged(extractDir)`, is about ownership rather than UI: `/graph/load-file` hands the host the temp directory a package was extracted to (empty for bare JSON, `/graph/load` and `/graph/clear`), and the host keeps it while the graph uses it and deletes the previous one. The GUI adds it to its heartbeated extracted-media list on the UI thread; headless moves its extract-directory guard to it.

See [Threading Model](threading-model.md) for the full UI / render-worker split and the offscreen-blit composition path.

The GUI's own 20 routes are UI-coupled or host-specific: the canvas and preview (`/graph/snapshot`, `/graph/view*`, `/preview/view*`, `/render/preview-node`, `/render/capture`, `/render/pixel-trace`, `/graph/rename-node`), the GPU adapter (`/gpu/list`, `/gpu/switch`), node logs, and the perf routes (`/perf*`, in `Controls/PerfMcpRoutes`). They are registered through `Controls::McpRouteTable`, which runs each on the UI thread, the render worker or the session thread as it declares ([threading](threading-model.md#mcp-routes)). `/context` is an engine route, so headless serves it too. `POST /` (the JSON-RPC dispatcher) is engine-registered on both hosts via `RegisterJsonRpcEndpoint`.

## Engine ABI version

`SHADERLAB_ENGINE_ABI_VERSION` (`EngineExport.h`) is bumped by hand whenever an exported symbol's signature, an exported class's layout or a public behaviour changes in a way that breaks a host built against older headers. It is independent of `Version.h`'s app version and `GraphFormatVersion`. Every host calls `ShaderLab_GetAbiVersion()` at startup and aborts on a mismatch, which turns a stale incremental build into a clear error instead of an access violation at a shifted field offset. A version that has not shipped yet takes further changes without another bump. History of compatibility-breaking changes:

- **1:** Initial engine DLL.
- **2:** McpHttpServer renamed McpRouter, Response extracted to ShaderLab::Mcp::Response (McpTypes.h) with a noReply discriminator, Handler gains a query argument, IEngineCommandSink::Dispatch re-typed accordingly, EngineContext gains getPipelineFormatName.
- **3:** the HTTP transport is deleted. McpRouter loses Start/Stop/Port/IsRunning + the Winsock listener (keeps AddRoute/RouteRequest/HasRoute); the broker (shim → hub → session) is the only transport. ActivityCallback's peer arg becomes clientId.
- **4:** Layout changes to exported types, accumulated over the GPU-timing and tiling work: EffectNode gains lastGpuMs / gpuState / clockTickBucket, CustomEffectDefinition gains lookupInputCount, GraphEvaluator gains the GPU timer, dispatch counter and pull-propagation set, and D3D11ComputeRunner is newly exported. A host built against v3 headers reads these at the wrong offsets -- the exact access violation inside the engine DLL that a stale incremental build produced mid-session.
- **5:** Performance pass. GraphEvaluator drops the Evaluate-time pre-render and gains content-addressed variant/reflection memos, split analysis targets and async-readback bookkeeping; D3D11ComputeRunner's single staging buffer becomes a ring and its readback flag an enum.
- **6:** User effects and option variants. Layout changes to ShaderLabEffectDescriptor (sourcePath), ShaderLabEffects (load report), VideoSourceProvider (m_convertCtx), ParameterDefinition (specialize), EffectNode (variantsCompiling), BytecodeCompileKey (optionKey) and GraphEvaluator (variant state); a new IEngineCommandSink virtual (OnGraphMediaDirChanged), EffectGraphFile::LoadResult (package) and Mcp::EngineContext (renderFrameFor).
- **7:** ShaderLabEffectDescriptor gains deriveImageOutputSize; D3D11ComputeRunner gains the two-pass image contract (accumulator, pass constants); VideoSourceProvider's decode-ahead queue, PlayTo and learned keyframe spans, and SourceNodeFactory without its paused-clock map and with its past-the-end black images. FrameExecutor, SourceRuntime and Graph/ClockModel are added (SetClocksToTime / LongestClockDuration move from Rendering to Graph); GraphEvaluator::Evaluate takes an EvalMode and SetDeferredComputeFrozen is gone; SourceNodeFactory's tick functions take std::span<EffectNode>.
